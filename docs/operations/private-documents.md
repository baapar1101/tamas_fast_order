# فایل‌های خصوصی مشتریان

مدارک هویتی، گزارش ICS24، جواز، تصاویر چک و رسیدها در فضای جدا از `STORAGE_ROOT` نگهداری می‌شوند. مسیر پیش‌فرض، پوشهٔ `private-storage` کنار storage عمومی است. `PRIVATE_STORAGE_ROOT` نباید زیر web/public، web/dist یا storage عمومی قرار گیرد.

## دسترسی

- لینک فایل `/api/files/:id` است؛ کوکی نشست یا Bearer معتبر لازم است.
- مالک پرونده، حتی پیش از تأیید اولیهٔ حساب، سند خود را می‌بیند.
- مدیر فعال مجاز است؛ اپراتور `manage_users` مدارک اعتباری و رسیدها را می‌بیند. اپراتور صرفاً دارای `manage_orders` فقط رسید پرداخت را می‌بیند، نه مدارک اعتباری.
- کتابخانهٔ رسانه سند خصوصی را فهرست یا حذف نمی‌کند. کاربر نمی‌تواند فایل حساب دیگر یا URL خارجی را به پروندهٔ خود متصل کند.
- پاسخ فایل و خطاهای آن `private, no-store` است؛ نام اصلی فایل در URL نیست و دانلود موفق در audit_log ثبت می‌شود.
- ورود، کوکی نشست `HttpOnly` و `SameSite=Lax` صادر می‌کند؛ در تولید `Secure` است. نشست‌های قدیمی Bearer در درخواست معتبر `GET /api/auth/me` به همین کوکی متصل می‌شوند تا لینک PDF و تصویر بدون قراردادن توکن در URL باز شود. درخواست‌های تغییردهنده با احراز هویت صرفاً کوکی، Origin هم‌دامنه می‌خواهند؛ Bearer همچنان برای کلاینت‌های API پشتیبانی می‌شود.

## انتشار و مهاجرت امن

۱. از دیتابیس و پیکربندی Nginx بکاپ محدود به مالک بگیرید. فایل‌های قبلی را پیش از تأیید کپی حذف نکنید.

۲. build را کامل کنید، سپس migration افزایشی 0027 را اعمال کنید. DDL زمان ثبت route حذف شده؛ انتشار همیشه باید `npm run db:migrate` داشته باشد.

۳. از `apps/api` اجرا کنید:

```sh
npx tsx scripts/privatize-documents.ts
npx tsx scripts/privatize-documents.ts --write
```

حالت اول فقط برنامه و شمارش را گزارش می‌کند. حالت دوم قبل از تغییر لینک‌ها، کپی خصوصی و checksum را تأیید می‌کند؛ سپس اشاره‌گرها را در تراکنش تغییر می‌دهد و اصل عمومیِ یکسان را جابه‌جا می‌کند. manifest قبل از تغییر در `.private/document-migrations/` با مجوز 0600 باقی می‌ماند. فایل مفقود، تعارض استفادهٔ عمومی/خصوصی یا چند مالک، فرایند را متوقف می‌کند. اسناد بدون مرجع از نوع other محافظه‌کارانه خصوصی می‌شوند؛ رسانهٔ متصل به کالا/برند/بنر حفظ می‌شود. فایل خارجی خودکار دانلود نمی‌شود.

فقط اگر با بررسی مستقل و بکاپ ثابت شد فایل‌هایی **از قبل** مفقود بوده‌اند، می‌توان شناسه‌های دقیق آن‌ها را با `--allow-missing=2,3` به هر دو دستور مهاجرت و راستی‌آزمایی داد. این گزینه فایل را بازیابی نمی‌کند و نباید برای نادیده‌گرفتن خطای جدید استفاده شود؛ متادیتا و تاریخچهٔ همان رکوردها باقی می‌ماند. انتشار ۲۳ اکتبر ۲۰۲۶، ۹ مورد ازپیش‌مفقود با شناسه‌های ۲ تا ۱۰ داشت؛ باینری آن‌ها در منابع بررسی‌شده پیدا نشد و به نسخهٔ اصلی یا آپلود مجدد نیاز دارند.

۴. سرویس موجود aaPanel را بازخوانی کنید. Nginx **نباید** storage را با alias به‌طور مستقیم سرو کند:

```nginx
location ^~ /uploads/ {
    proxy_pass http://127.0.0.1:3102;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_cache off;
}
```

API تصاویر عمومی را با کش سرو می‌کند، ولی لینک قدیمی سند فقط پس از احراز مجوز به مسیر خصوصی هدایت می‌شود؛ برای مهمان 404 است. هنگام پنجرهٔ انتشار می‌توان موقتاً فقط مسیر certificate/other را بست تا هیچ فاصلهٔ بدون حفاظت رخ ندهد.

۵. پس از `nginx -t` و reload، `npx tsx scripts/verify-private-storage.ts` را اجرا کنید. این تست همهٔ اصل‌ها/thumbnailهای خصوصی، پاسخ بی‌نشست و سه تصویر عمومی را بررسی می‌کند. مشاهدهٔ سند از پنل مدیر هم با مرورگر آزموده شود.

## بازیابی و بکاپ

دیتابیس، storage عمومی و private-storage را با هم بکاپ بگیرید. بکاپ روزانهٔ تلگرام فعلی فقط دیتابیس است و باینری مدارک را شامل نمی‌شود. در rollback کد، فایل‌ها را دوباره عمومی نکنید؛ مسیر خصوصی را فعال نگه دارید. manifest برای تطبیق و بازیابی مدیریتی است، نه بازکردن عمومی لینک‌های قدیمی. نسخه‌ای که قبلاً دانلود یا کش شده از دستگاه گیرنده قابل پس‌گرفتن نیست.

## نتیجهٔ انتشار ۲۳ اکتبر ۲۰۲۶

۳۴ رکورد خصوصی شدند؛ ۴۹ فایل موجود پس از تطبیق checksum به فضای خصوصی منتقل شدند و ۶۷ نشانی قدیمیِ اصل/بندانگشتی برای مهمان مسدود است. تصاویر عمومی محصولات همچنان پاسخ ۲۰۰ دارند. مشاهدهٔ PDF با نشست مدیر و ثبت رخداد دسترسی نیز تأیید شد. بکاپ تراکنشیِ فقط‌خواندنی همهٔ ۴۱ جدول، به‌صورت JSON فشرده با مجوز 0600 در مسیر زیر نگهداری شد؛ این فایل جایگزین باینری مدارک یا یک pg_dump قابل‌بازیابی مستقیم با psql نیست:

`/www/wwwroot/tamas_fast_order/apps/api/.private/release-backups/before-private-documents-1792781854988.json.gz`

manifest مهاجرت: `/www/wwwroot/tamas_fast_order/apps/api/.private/document-migrations/before-1792782217786.json`. نسخه‌های پشتیبان Nginx در همان `.private/nginx-backups/` قرار دارند. هیچ‌یک از این فایل‌های حساس وارد Git نشده‌اند.
