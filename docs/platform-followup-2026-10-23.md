# پیگیری ممیزی و انتشار امن — ۲۳ اکتبر ۲۰۲۶

این گزارش ادامهٔ [ممیزی اولیه](platform-audit-2026-10-23.md) است. تغییرات روی سرویس موجود aaPanel منتشر شدند؛ سرویس موازی، سفارش آزمایشی واقعی، تراکنش بانکی یا تغییر اعتبار مشتری ایجاد نشد.

## اصلاحات انجام‌شده

| حوزه | نتیجه |
|---|---|
| مدارک و رسیدها | storage خصوصی خارج از ریشهٔ عمومی، مجوز مالک/مدیر/اپراتور، لینک محافظت‌شدهٔ `/api/files/:id`، هدرهای no-store و ثبت رخداد خواندن. چک، رسید قسط، مدارک درخواست اعتبار، گزارش ICS24 و جواز پروفایل پوشش داده شدند. |
| جلوگیری از اتصال سند دیگران | اتصال فایل به درخواست، چک، پروفایل یا اطلاعات پرداخت فقط پس از اعتبارسنجی مالکیت انجام می‌شود؛ URL خارجیِ جدید جای فایل پذیرفته نمی‌شود. مقادیر قدیمیِ تغییرنکرده بدون دانلود خودکار حفظ شدند. |
| نشست مرورگر | کوکی HttpOnly/Secure/SameSite و اتصال نشست‌های قدیمی Bearer از `/api/auth/me`؛ PDF و تصاویر خصوصی بدون قراردادن توکن در URL باز می‌شوند. درخواست تغییردهندهٔ cookie-only به Origin معتبر محدود شد. پاسخ ورود/نشست کش نمی‌شود. |
| مهاجرت داده | migration افزایشی 0027 و index/constraint مالکیت اضافه شد؛ DDL زمان ثبت route و catch بی‌صدا حذف شد. خروجی مجدد تولید schema تغییری نداشت. |
| لایهٔ وب‌سرور | alias مستقیم `/uploads/` با proxy به کنترل مجوز API جایگزین شد؛ هنگام انتقال، مسیر حساس موقتاً بسته بود. تنظیم Nginx پس از بکاپ با آزمون پیکربندی و reload فعال شد. |
| دیزاین‌سیستم | رنگ‌های معنایی، فونت Vazirmatn FD، مقیاس اندازه و فاصله، حالت روشن/تیره، فوکوس، جدول، دکمه و مودال در فایل‌های فعال هماهنگ شدند. CSSهای قدیمی از adapter مشترک استفاده می‌کنند. فرم جواز به آپلود خصوصی تبدیل شد؛ کنترل‌های کیف پول و ورودی‌های موبایل نیز اصلاح شدند. |
| ایمنی تغییر ظاهر | ابزار migration آگاه از property و AST فقط CSS و inline style را تغییر می‌دهد، نه داده‌های تجاری. چاپ/کاتالوگ با ابعاد ثابت و پالت تصویری از بازنویسی کور مستثنا هستند. `normalize-ui-tokens --check` اکنون صفر مغایرت دارد. |
| عملکرد مدیریت | صفحات مدیریت route-level و تنبل شدند؛ chunk اصلی AdminApp از حدود ۵۵۰KB به ۵۴٫۱۹KB خام رسید. PDF و اکسل همچنان جدا و تنبل بارگذاری می‌شوند. |
| به‌روزرسانی وب‌اپ | نسخهٔ جدید اعلان می‌شود و فرم ناتمام خودکار reload نمی‌شود. پاک‌سازی تنها برای cache و service-worker متعلق به تماس مارکت و با انتخاب کاربر انجام می‌شود. فایل‌های هش‌دار قبلی هفت روز نگهداری می‌شوند. این تغییر ادعای پشتیبانی آفلاین کامل نیست. |
| کیفیت و پیشگیری | ESLint و config اجرایی، بررسی توکن‌ها در CI، تست‌های واقعی HTTP فایل خصوصی/نشست/CSRF و قرارداد رابط اضافه شد. الگوی بکاپ env و کلید Google service account نیز از ثبت ناخواسته در Git مستثنا شد. |
| سیاست پرداخت | انتخاب مالک «فاکتور جدا برای موبایل و جانبی» ثبت شد؛ محدودیت فعلی سبد ترکیبی و محاسبات پرداخت آن تغییر نکرد. |

## نتیجهٔ انتقال روی تولید

- ۳۴ رکورد upload خصوصی شدند و ۲۳ ارجاع سند بازنویسی شد.
- ۴۹ فایل موجود، پس از کپی و تطبیق checksum، به private-storage منتقل شدند. اصل‌های عمومی یکسان حذف شدند، اما نسخهٔ خصوصی و manifest برای بازیابی مدیریتی محفوظ است؛ فایل سالمی بدون نسخهٔ جایگزین حذف نشد.
- هر ۶۷ نشانی قدیمیِ اصل/بندانگشتی در آزمون بی‌نشست مسدود بود؛ مسیر canonical برای مهمان ۴۰۱ و تصویر عمومی محصولات ۲۰۰ بود.
- PDF از پنلِ دارای نشست مدیر باز شد و رخداد `private_document` در audit_log ثبت شد. تست HTTP نقش‌ها نیز مالک، حساب دیگر، مدیر و اپراتور دارای/فاقد مجوز را پوشش می‌دهد.
- **۹ فایل با شناسه‌های ۲ تا ۱۰ پیش از این انتشار مفقود بودند.** در storageهای قبلی و منابع بکاپ بررسی‌شده پیدا نشدند. metadata و تاریخچه‌شان حفظ شد؛ برای محتوای آن‌ها نسخهٔ اصلی یا آپلود مجدد لازم است. اجازهٔ عبور فقط برای همین baseline صریح داده شد، نه هر فایل مفقود آینده.
- سه مقدار legacy پروفایل منبع محلیِ قابل‌انتقال نبودند؛ بدون ارسال درخواست به URLهای دلخواه یا تغییر دادهٔ قبلی حفظ شدند.

راهنمای مجوزها، مسیر بکاپ تراکنشی ۴۱ جدول، manifest، پیکربندی Nginx و بازیابی در [راهنمای عملیات مدارک خصوصی](operations/private-documents.md) آمده است. بکاپ باینری مدارک باید جداگانه نگهداری شود؛ بکاپ روزانهٔ تلگرام فعلی فقط دیتابیس را شامل می‌شود.

ابعاد مرورگر ۳۹۰×۸۴۴ و ۱۴۴۰×۱۰۰۰ بود. [ماتریس ۱۶۰ بررسی](audit-evidence/followup-ui-matrix-2026-10-23.json) فقط مسیر، تم و معیارهای DOM را دارد؛ اطلاعات هویتی، توکن یا متن پرونده در آن ذخیره نشده است. نمونهٔ بصری: [صفحهٔ محصول موبایل](audit-evidence/followup-product-mobile-2026-10-23.jpg). تم و ابعاد مرورگر پس از بررسی به وضعیت قبلی برگشتند و تب موقت بسته شد.

این بررسی با نشست مدیر موجود، خواندنی و برای رندر صفحات بود؛ اجرای تمام فرم‌ها، نقش مشتری تازه و همهٔ ترکیب‌های داده یا دستگاه فیزیکی را اثبات نمی‌کند. یک مسیر تحلیل در بررسی نخست بیش از مهلت ۱۰ثانیه آماده شد؛ پس از آماده‌شدن و با مهلت ۲۰ثانیه، بررسی ادامه یافت.

## مواردی که هنوز اقدام جدا می‌خواهند

1. تعویض کلیدهای CRM، webhook و PIN قبلاً در معرض دسترس، نیازمند صدور مقدار جدید در پنل سرویس‌های مالک است. مقدار تصادفی جایگزین نشد تا اتصال قطع نشود. حذف از کد یا پاسخ API، نسخه‌های قبلی را باطل نمی‌کند.
2. ۹ باینری ازپیش‌مفقود فقط با نسخهٔ اصلی/بکاپ مستقل یا آپلود مجدد قابل‌بازیابی‌اند.
3. آزمون واقعی sandbox درگاه و تطبیق حالت‌های already-verified/سفارش لغوشده، با credential و سناریوی بانکی مجاز لازم است؛ در این انتشار وجهی منتقل نشد.
4. چهار هشدار متوسط ابزار توسعهٔ Drizzle Kit در زنجیرهٔ esbuild قدیمی باقی است. override آزمایشی graph معتبر نساخت و کنار گذاشته شد؛ downgrade اجباری یا ارتقای ناسازگار ابزار migration منتشر نشد. وابستگی اجرایی هشدار ندارد.
5. PDF حدود ۷۷۷KB خام و تنبل است و هشدار اندازهٔ build باقی می‌ماند. برای suite مرورگر پایدار نقش‌های مشتری/اپراتور با دیتابیس و fixture مستقل، کار تکمیلی لازم است؛ تست‌های HTTP این انتشار جای آن را کامل نمی‌گیرند.

موارد تاریخی TLS/کاربر پردازش در [راهنمای aaPanel](operations/aapanel-deployment.md) نباید بدون بررسی دوبارهٔ تنظیم زنده، حل‌شده فرض شوند. در این انتشار مدیریت سرویس به aaPanel باقی ماند.
