## 2024-05-24 - Precomputing Map grouping for O(N*M) lookups inside `.flatMap()`
**Learning:** In the `apps/api/src/routes/credit.ts` route, a performance bottleneck specific to this codebase's architecture was identified where a `.filter()` was used to count items matching an ID inside a `.flatMap()` loop. This caused an O(N*M) time complexity, iterating over a list of cheques for every customer order. The `.length` property was then checked on the resulting filtered array.
**Action:** When iterating over a collection (e.g. `orders`) using `.map()` or `.flatMap()`, and needing to correlate or aggregate data from another collection (e.g. `chequesList`), precompute an aggregation `Map` prior to the loop. In this instance, precomputing a `Map<number, number>` counting cheques by `orderId` allowed for an O(1) `.get()` lookup inside the `.flatMap()` loop, reducing the complexity to O(N+M).
