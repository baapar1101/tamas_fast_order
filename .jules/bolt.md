## 2024-05-30 - O(N) Product Duplicate Detection Bottleneck
**Learning:** `findProductDuplicate` in `apps/api/src/services/product-duplicates.ts` fetches the entire active product table into memory to perform duplicate detection in JavaScript. The user explicitly required a mathematically sound SQL prefilter (proving it preserves all normalized identity matches, including Persian/Arabic digits, uppercase/lowercase and whitespace differences) or no changes at all. Without adding an extra `normalized_identity` column to the schema or complex postgres triggers, an exact equivalent purely in SQL `where` conditions for the `normalizeProductIdentity` logic (which strips out non-alphanumeric unicode characters, unifies Arabic/Persian letters, trims spaces, and standardizes digits) is highly complex and risky. A partial SQL prefilter might miss edge cases unless we do extensive index building. Thus, doing a risky PR to solve this is not advisable without adding a dedicated column.
**Action:** Do not attempt to optimize `findProductDuplicate` with SQL approximations if it risks changing exact duplicate detection semantics.
