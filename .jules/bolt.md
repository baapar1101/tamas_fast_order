## 2024-05-18 - Replacing N+1 Array.find() inside loops with Pre-computed Maps
**Learning:** In the codebase, it is a common anti-pattern to call `.find()` on an array inside a `.map()` or `for` loop, especially when mapping rows or joining related data across arrays (like attaching instructions to orders, or mapping inventory products to their DB row equivalents). Converting a Map to an array with `[...map.values()]` inside a loop just to call `.find()` is especially costly because it re-allocates the array on every iteration.
**Action:** When joining or cross-referencing collections inside a loop, pre-compute a `Map` keyed by the shared ID before the loop (e.g., `const lookup = new Map(items.map(i => [i.id, i]))`). Then, replace the $O(N^2)$ `.find()` with an $O(N)$ `.get()` lookup inside the loop. This provides massive performance benefits with virtually zero risk to correctness.
